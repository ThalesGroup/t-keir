Developer Integration Checklist and Example Patterns for SDKs and Docs

Overview

Purpose: This page is a single-stop checklist and pattern catalog for SDK authors, docs authors, and on-call engineers who publish or maintain SDKs, quickstarts, API examples, and docs-site content. It combines a publishing checklist, snippet library governance, example API patterns (good + bad), docs-site operating commands, and canonical fixes for the top support issues we observe in the DX queue.

Audience: SDK engineers, developer-docs authors, support engineers, and release owners.

1) Publishing checklist (SDKs, quickstarts, snippets)
Follow these steps before merging a PR that changes public-facing SDK code or docs snippets. Fail-open items block CI if missing: unit tests, snippet lint, docs preview.

Required (pre-merge):
1) Confirm API contract: update openapi/schema if the surface or request/response shape changed. Include example payloads in examples/ directory.
2) Unit and integration tests: >= 90% coverage for new modules + stable CI runs.
3) Snippet validation: run tools/snippet-lint --path <changed_files>. Ensure snippet passes naming and size limits.
4) Docs preview: create a docs preview build and attach the preview URL in the PR. Command: 
   - make docs-preview || ./scripts/docs_build.sh --pr $PR_NUMBER && ./scripts/publish_preview.sh --pr $PR_NUMBER
5) Backward-compatibility note: include a short migration note if behavior or defaults changed. Add a ‘breaking-change’ label if needed.

Optional (recommended):
- Add or update a quickstart in quickstarts/ with step-by-step copy/paste commands.
- Add a minimal e2e example using the client in examples/ with a small recorded golden output.

2) Snippet library governance
Naming conventions (enforced by snippet-lint):
- category/feature-language-variant.extension; example: auth/getting-started-python.py, chat/stream-js.js
- Max snippet length: 60 lines. If longer, break into multiple focused snippets.
- Metadata header required: // owner: team-name | tags: sdk, quickstart | expires: YYYY-MM-DD

3) Canonical API examples: good vs bad patterns
Example: simple text generation (pseudocode).
Bad pattern (anti-pattern): blocking call with long timeout + no retry/backoff
```
# bad: blocks for 60s, no retry
response = client.generate(prompt, timeout=60000, retries=0)
print(response.text)
```
Good pattern (recommended): explicit shorter network timeout, streaming when appropriate, retry with exponential backoff, and per-request idempotency token when applicable
```
# good: streaming + retry policy + timeout
with client.stream.generate(prompt, stream_handler=on_token) as s:
    s.configure(timeout_ms=5000, retry_policy="exponential", max_retries=3)
    s.start()
```
Python example (curl + minimal):
```
# Python example: safe generate
from redwood_sdk import RedwoodClient
client = RedwoodClient(api_key="$REDWOOD_KEY", default_timeout_ms=5000)
resp = client.generate("Translate to French: Hello world", max_tokens=80)
print(resp.text)
```
Curl example for support reproduction:
```
curl -sS -X POST "https://api.redwood.ai/v1/generate" \
  -H "Authorization: Bearer $REDWOOD_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"rwd-small-1","prompt":"Summarize: ...","max_tokens":120,"timeout_ms":5000}'
```
Notes: always include model name and a numeric timeout_ms in reproducible examples; this minimizes triage time.

4) Docs-site operating procedures (authors + release ops)
Short runbook: update -> preview -> smoke -> release.
- Local build: npm run docs:dev (runs mkdocs + local snippets watcher)
- Preview build (CI): docs-ci pipeline will run on PR. Required checks: snippet-lint, link-check, spell-check, accessibility-check.
- Smoke checklist for preview reviewers:
  1) Validate key quickstarts run end-to-end in the preview (copy commands and run locally)
  2) Validate code snippets execute (use snippet-runner container)
  3) Verify tables render correctly and images are present
- Release: after two approvals and passing CI, merge to main triggers docs-ci -> publish to docs.redwood.ai. For hotfixes, set #hotfix label and tag the release: git tag -a docs-hotfix-YYYYMMDD && git push origin main --tags && docs-ci trigger --hotfix

5) Top DX support issues and canonical fixes (triage + known remediation)
Issue pattern: streaming disconnects under TLS + intermittent 50x from runtime.
- Symptom: client receives partial stream, then socket closes.
- Triage steps:
  1) Reproduce with curl using --no-buffer to see chunking: curl --no-buffer ...
  2) Check client network (proxy / corporate TLS interception). If corporate proxy, suggest bypass or increase keepalive.
  3) Check runtime logs for connection resets (service: rwd-runtime-streaming) and correlate request_id.
- Canonical fix for SDKs: implement automatic reconnect with resume token and idempotency. Example pattern:
```
# SDK pseudocode: resume tokens
stream = client.stream.start(prompt)
for token in stream:
    if connection_lost:
        new_stream = client.stream.resume(resume_token=stream.resume_token)
        stream = new_stream
```
Issue pattern: high token cost from accidental greedy loops (prompting bug).
- Symptom: unexpectedly high cost spike traced to a client that repeatedly called generate in a loop.
- Canonical remediation:
  - Add safeguards in quickstarts: show how to set max_tokens and stop sequences.
  - Add quota-friendly example using lower temperature and max_tokens, and show batch sampling if many prompts are required.

Issue pattern: timeouts on long context window requests (>= 32k tokens).
- Symptom: request times out; logs show memory pressure in serving runtime.
- Triage steps:
  1) Ask customer for sample prompt + model. Reproduce in perf lab with rwd-large-32k profile.
  2) If reproducible, suggest chunked generation or streaming.
- Canonical fix: update quickstarts to include chunking example (split into context windows and rehydrate KV cache). Example pseudo-command:
```
# chunking pattern: pseudo
chunks = chunk_prompt(large_prompt, window=8192)
state = None
for c in chunks:
    resp, state = client.generate_chunk(c, kv_state=state)
```

6) Support triage template for PRs and incidents
Include these fields when filing a DX support ticket or creating a regression PR:
- Title: short summary + reproducible phrase (e.g., "stream disconnects when using corp-proxy")
- Steps to reproduce: minimal curl + environment (OS, node/python version, proxy true/false)
- Expected behavior vs actual behavior
- Request ID(s) / timestamps (if available)
- Attach reproduction snippet (no secrets) and a brief smoke test script that the reviewer can run in <5 minutes
- Suggested fix and rolling strategy (canary percent, config to change)

7) Templates and snippets to include in quickstarts (copy/paste)
- Minimal auth example (LANG: python, js)
- Streaming safe consumer (resume token pattern)

- Local mock server for offline docs dev (mock-server config snippet)

Example: embeddings batching (NodeJS)
```
// embedding-batch.js
const client = new RedwoodClient({ apiKey: process.env.REDWOOD_KEY, timeout: 10000 })
async function embedBatch(lines){
  const batchSize = 64
  const batches = chunkArray(lines, batchSize)
  const results = []
  for(const b of batches){
    const resp = await client.embeddings.create({ model: 'rwd-embed-2', input: b })
    results.push(...resp.data)
  }
  return results
}
```
