Operator training curriculum and competency framework for private deployments

Overview
=======
This document defines the Operator Training Curriculum and Competency Framework for Redwood Private Deployments (VPC and on‑prem). It is intended for Redwood field operators, partner system integrators, and internal onboarding teams. The curriculum bridges deployment guides, day‑2 operations, on‑prem packaging, upgrade and rollback procedures, and customer readiness requirements so operators can safely commission, maintain, and recover private clusters to SLAs.

Scope
-----
- Audience: Redwood operators, SREs assigned to customers, partner support engineers.
- Environments: VPC Private Deployments, air‑gapped on‑prem, and hybrid control plane topologies.
- Outcomes: Certified operators who can perform preflight validation, model swap/quantization rollouts, telemetry onboarding, incident mitigation, and forensics‑grade rollback.

Certification levels and expected capabilities
--------------------------------------------
We use a three‑tier competency model. Each level has measurable outcomes and associated exercises.

1) Level 1 — Field Qualified (L1)
   - Can execute preflight checklists, start/stop operator services, and collect targeted telemetry.
   - Understands Redwood control plane handshake and tenant commissioning flow.
   - Can run smoke validation and the customer acceptance test suite.
   - Minimum exam: run a smoke test and resolve a simulated KV cache cold start within target thresholds.

2) Level 2 — Deployment Operator (L2)
   - All L1 plus: can perform a model swap with canonical rollback, tune autoscale policies, and implement policy‑driven tenant throttles.
   - Able to read kernel scheduling traces and identify contention hotspots for the serving runtime.
   - Minimum exam: perform a canary model rollout and, after injected failure, run the rollback procedure with evidence preservation.

3) Level 3 — Forensic & Upgrade Lead (L3)
   - All L2 plus: leads controlled rollouts across multi‑region/private clusters, designs fallback topologies and executes post‑incident forensic preservation.
   - Responsible for creating upgrade backout matrices and certifying operator teams for customer handoff.
   - Minimum exam: lead a 2x model swap under load, perform live traffic routing split, and deliver an incident report and preserved artifacts for compliance.

------------------------------------------

-----|----------------|---------------------------------------------------------

Curriculum outline and modules
------------------------------
Each module contains reading, hands‑on labs, and an objective assessment. Recommended sequence: Modules 1→8.

Module 1 — Private Deploy Foundations (self‑study, 2h)
- Redwood architecture: control plane variants, data paths, and tenant isolation patterns.
- Reference diagrams: regional‑proxy fabric, split‑horizon control plane.

Module 2 — Preflight and Customer Readiness (lab, 3h)
- Run the Customer Acceptance Test Suite (CAT 20) and interpret results.
- Minimum HW/network table (sample):

| Component | Minimum | Recommended | Rationale |
|---|---:|---:|---|
| GPU (per node) | A100‑40GB | A100‑80GB / H100 | model swap headroom and KV cache size
| NVMe | 2x 3.2TB | 4x 7.6TB | snapshot throughput for stateful migration
| Control plane RTT (intra‑region) | <5ms | <2ms | low latency for model swap orchestration
| Egress circuit | 1Gbps | 10Gbps | bulk model artifact refreshes

Module 3 — On‑prem packaging & airgap (lab + checklist, 2.5h)
- Image signing verification, artifact manifest format, and attestation flow.
- Offline KMS integration pattern and HSM fallback.

Module 4 — Observability and Telemetry Onboarding (lab, 3h)
- Token‑level cost/latency sampling, per‑route dashboards, and sampling retention policies.
- How to configure log sampling: sample rates, labeling, and sensitive fields redaction.

Module 5 — Day‑2 Operations (hands‑on drills, 4h)
- Capacity and thermal drift detection, hot‑swap of model artifacts, and tenant eviction procedures.
- Runbook excerpt (example steps):
  1. Identify degradation via SLO alert (p95 latency > 250ms for 5m).
  2. Isolate tenant / traffic divert to fallback model variant.
  3. Open a field ticket and attach trace IDs and matching KV cache snapshot id.
  4. If not remediated in 15m, trigger controlled rolling eviction based on entitlement.

Module 6 — Upgrade, Canary and Rollback Playbook (lab + scenario, 4h)
- Canary strategy, safety gates, and automated rollback hooks.
- Required artifacts for rollback: snapshot id, KV cache digest, model artifact checksum, operator evidence bundle.

Module 7 — Forensics and Evidence Preservation (workshop, 3h)
- How to preserve forensics with minimal service disruption.
- Evidence bundle template (artifact names):
  - operator_evidence_bundle.tar.gz
  - topology_snapshot.json
  - telemetry_slice_{start}_{end}.ndjson
  - cryptographic_checklist.txt

Module 8 — Compliance & Customer Handoff (roleplay, 2h)
- Handback checklist, documentation templates for legal & security, and SLAs.

Runbook: Canary rollout + safe rollback (concise procedure)
-------------------------------------------------------
1) Preflight (30–60m)
   - Validate staging telemetry, ensure no active slowdowns, confirm model checksums.
   - Lock quota windows for target tenants.
2) Canary push (stepwise)
   - Deploy to 2% of traffic; monitor latency, error rates, token cost delta.
   - Wait 10m; if OK, increase to 20% and run AB quality checkset (promptset ID: ps‑deploy‑2026‑v1).
3) Safety gate checks (automated)
   - p95 latency delta < 10ms, error rate delta < 0.1%, quality regression < 1% on prompts.
4) Rollforward or Rollback
   - On failure: execute rollback script:
     ./operator-scripts/rollback-to-stable.sh --snapshot <snapshot-id> --keep-evidence true
   - Preserve the evidence bundle and mark the event in the incident tracker (tag: deploy‑rollback).

Operator lab scenarios (examples)
-------------------------------
- Scenario A: KV cache corruption during model swap — detect, isolate, and restore from snapshot.
- Scenario B: WAN egress failure — rehome core routing to regional fallback and document TTL impact.
- Scenario C: HSM token rotation during live traffic — failover to software KMS in read‑only mode and schedule maintenance window.

Assessment and continuous learning
--------------------------------
- Each exam is pass/fail with scoring rubrics: checklist completion, time to remediation, and quality of evidence.
- Quarterly re‑certification for L2/L3 recommended, triggered by significant runtime changes (new kernel, quantization profile, or control plane patch).

Operator tooling and artifact references
-------------------------------------
- operator-scripts/ (repo) — rollout and rollback helpers. Example: operator-scripts/canary-analyze.py
- cat‑suite/ — acceptance tests and prompt sets (ps‑deploy‑2026‑v1).
- telemetry‑contracts.md — per‑tenant sampling and retention defaults.
