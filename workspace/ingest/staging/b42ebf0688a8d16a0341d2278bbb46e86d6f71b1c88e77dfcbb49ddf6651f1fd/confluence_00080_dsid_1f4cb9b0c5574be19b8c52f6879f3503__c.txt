capability-prioritization-and-release-playbook-2027

Summary:

This document captures a prioritized capability roadmap for the Redwood Inference product surface (Hosted API, Dedicated, Private) focused on 12 months of incremental releases and the accompanying release playbook and pricing implications. It is intended to be an operationally-actionable artifact: each capability has acceptance criteria, required engineering dependencies, an SLO mapping, and proposed packaging/pricing moves.

Audience:
- Product managers and PMMs
- Engineering leads (serving runtime, platform, private deployments)
- Sales, solution engineering, and customer success teams

High-level objectives:
- Increase conversion from trials to Dedicated/Private for regulated customers by improving determinism and compliance features.
- Reduce top-customer per-token spend by enabling conservative quantization + batching paths with validated quality regression controls.
- Establish at least one SLO-backed product tier that is monetizable with measurable uplift.

Customer personas and primary problems:
1) Platform Engineer (mid-market SaaS) – needs predictable 99th percentile latency and straightforward routing controls to avoid user-facing flakiness.
2) ML Engineer (AI-native startup) – needs cheap experimental variants and an easy way to compare quality vs cost tradeoffs.
3) Security/Compliance Lead (enterprise) – requires on-prem installers, audit logs, and deterministic upgrade procedures.

Capability waves (prioritized):
Wave A (Q1-Q2 2027): Deterministic latency + observability - Acceptance criteria:
  - p95 <= 200ms for 512-token avg workloads in regional hosted clusters (measured over a 30-day window).
  - Console exposes per-route latency heatmap and token-cost breakdown; traces link to sampled request payloads. - Engineering work:
  - Serving runtime: tail mitigation (small-batch fast path) and KV cache eviction tuning.
  - Platform: tracing + cost telemetry ingestion + Console endpoints. - SLO mapping:
  - Latency SLO: p95 and p99 thresholds; availability SLO (99.95%). - Pricing impact:
  - No immediate pricing change; enable SLO-backed tier definition for Q3 launch. - Success metrics:
  - Reduction in demo failures reported by sales by 60%.
  - 25% fewer latency-related support escalations for top-10 customers.

Wave B (Q2-Q3 2027): Cost-optimized variants and quantization validation - Acceptance criteria:
  - Verified model variant catalogue with automated regression tests (ROUGE/BLEU or task-specific metrics) and quantization profiles for Top-5 open models.  - End-to-end tool that recommends one quantization profile and expected quality delta.
 - Engineering work:
  - Integrate validation harness into model onboarding pipeline.
  - Add Optimize suggestion engine into Console and API surface.
 - SLO mapping:
  - Cost regression guardrail: releases cannot increase median per-token cost by >10% for >7 days for >10 customers.
 - Pricing impact:
  - Introduce an optional "Economy Profiles" add-on that reduces per-token price by 12% for traffic routed to qualifying quantized variants; add-on requires model validation opt-in.
 - Success metrics:
  - 18% median per-token cost reduction for customers using Economy Profiles.

Wave C (Q3-Q4 2027): Hardened Private deployments and enterprise controls - Acceptance criteria:
  - Fully automated air-gapped installer image and documented network topology templates for two major cloud vendors.  - Audit log schema and KMS integration validated in two pilot customers.
 - Engineering work:
  - Private deployments: packaging, upgrade/rollback process, and day-2 ops playbook.
  - SRE: capacity reservation and deterministic autoscale hooks.
 - SLO mapping:
  - Deployment health SLOs for private installs (successful upgrades >= 95% across pilot fleet). - Pricing impact:
  - Bundle hardened private features into Private Enterprise package; charge implementation fee + annual maintenance.
 - Success metrics:
  - Two paid Private pilots converted to enterprise contracts within 90 days of pilot completion.

Release playbook (standardized steps):
1) Requirements (PM): clear acceptance criteria, API compatibility notes, list of affected customers and upward compatibility constraints.
2) Design review: architecture ADR, security review (if applicable), and an SLO impact assessment.
3) Staging validation: synthetic workload suite that mirrors customer token length distribution and multi-tenant noise.
4) Feature-flagged canary: 3-10 tenants on Dedicated or 1-2 internal accounts on Hosted for 14 days.
5) Gradual rollout with measured checkpoints: 10% -> 40% -> 100% of eligible traffic; each transition gated on stability and cost metrics.
6) Post-release review: 30-day telemetry digest and rollback retrospective documented in confluence.

Operational checklist before public launch:
- API docs and swagger updated with examples and deprecation notes.
- Console UI and user flows validated; beta users added to feature toggles.
- SLO dashboards and alerting playbooks created with escalation owners.
- Pricing collateral prepared: fact sheet, sales playbook, and objection handling.

Example acceptance criteria (explicit):
- API backwards compatibility: no change to existing endpoints; new parameters are optional and validated server-side.
- Performance: median token-processing throughput per instance must not decrease by >6% when the feature is enabled at scale.
- Quality guardrail: any model variant recommended must have a per-task metric delta <= 2% against the baseline model in the validation harness.

Risk matrix (top items):
- Hardware dependency: specific optimizations may depend on vendor drivers. Mitigation: maintain a tested compatibility matrix and degrade to a generic path with documented impacts. - Quality regressions from quantization: Mitigation: automated evaluation + staged canaries + human signoff for enterprise customers.
- Pricing misalignment: Early adopters may exploit discounts; Mitigation: limited-time trials and meterable feature tags.

Packaging & pricing guidance (practical):
- Latency SLO-backed tier: premium uplift of 15-25% on top of Dedicated base depending on target p95. Include priority routing and a 1-month SLA credit policy.
- Economy Profiles add-on: flat percentage discount on per-token invoice for traffic that is routed to validated variants. Add-on billed monthly and subject to usage gating.
- Private Enterprise: implementation fee (one-time) + annual support revenue; tiered by node-count and retention of audit logs.

Sample console feature flag snippet (for operations):
feature_flags:
  economy_profiles:
    enabled: true

API contract summary (text):
- New optional query parameters: variant_id (string), latency_tier (enum), economy_opt_in (bool).
- Error semantics: 422 when variant_id fails validation; 409 when customer quota prevents routing to chosen tier.

Success metrics to track per release (report weekly):
- Adoption: % of eligible customers who enable the feature within 30 days.
- Economics: median per-token cost delta for enabled customers vs baseline.
- Reliability: % of customers hitting SLO targets; incident counts attributable to new feature.
- GTM: number of deals explicitly citing the feature in win notes.
