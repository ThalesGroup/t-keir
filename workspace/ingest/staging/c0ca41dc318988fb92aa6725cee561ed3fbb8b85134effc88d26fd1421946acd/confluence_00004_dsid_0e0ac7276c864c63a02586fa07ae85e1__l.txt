Postmortem: Latency regression after tokenizer update (2026-01-27)

## Summary
On 2026-01-27 we observed a significant p95 latency increase for chat completions on several popular models. The regression began shortly after a tokenizer library update was rolled out to the hosted fleet.

## Customer impact
- Duration: 58 minutes
- Symptoms: p95 end-to-end latency +38% for affected routes; some customers hit client-side timeouts
- Scope: Hosted API traffic in us-east-1 and eu-west-1

## Detection
- Alert: route latency SLO burn for /v1/chat/completions
- Perf dashboards showed elevated CPU in prefill pipeline

## Timeline (UTC)
- 19:11: SLO burn alert fired
- 19:18: On-call correlates onset with tokenizer update rollout
- 19:30: Mitigation: rollback tokenizer update
- 20:09: Latency returns to baseline

## Root cause
A tokenizer update changed default normalization behavior, increasing average token counts and causing additional CPU overhead in request preprocessing. The change was not detected in canary because the canary prompt set did not include multi-language and emoji-heavy inputs that are common in production.

## Contributing factors
- Canary prompt set coverage gap
- Lack of automated guardrail on average tokens/request
- Rollout checklist did not include a CPU budget validation

## Follow-up action items
1. Expand canary prompt sets to include multilingual and special-character heavy inputs representative of production. Owner team: Applied ML. Priority: P0.
2. Add automated guardrail: alert when avg input tokens per request changes by >10% for a route/model over 15 minutes. Owner team: SRE. Priority: P1.
3. Add perf CI check for tokenizer updates (CPU per 1k chars, tokens per 1k chars) and require approval on regressions. Owner team: Serving Runtime. Priority: P0.
4. Update rollout checklist to include "tokenization cost" section and explicit rollback criteria. Owner team: Platform. Priority: P2.
5. Add a dashboard panel tracking avg tokens/request by top 20 customers (anonymized) to catch distribution shifts. Owner team: Observability. Priority: P1.

## Lessons learned
Seemingly minor preprocessing changes can have first-order latency impact. Production-like prompt sets and token-count guardrails are necessary for safe rollouts."
