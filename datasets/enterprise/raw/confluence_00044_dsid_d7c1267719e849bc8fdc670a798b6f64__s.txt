Slice Drift Sentinel and Quant Hedging Playbook

Overview

This playbook describes the Slice Drift Sentinel system and the Quant Hedging policy used across Redwood's eval harness to maintain user-visible fidelity while maximizing cost savings from quantized deployments. It covers detection signals, thresholds, automated hedging (fallback) rules, how to allocate cost 'shields' to high-risk slices, and the operational runbook for regression triage and rollback.

Motivation

- Quantized model variants decrease serving cost but occasionally produce regressions that are slice-specific (e.g., domain jargon, long context).
- We need automated, explainable controls to detect quality shifts at slice granularity and to migrate affected traffic to higher-fidelity variants with minimal manual intervention.
- The sentinel also provides cost accounting so product teams can accept controlled quality trade-offs.

Scope

Applies to: hosted and dedicated inference fleets, hybrid private deployments where telemetry is available.
Not covered: full retraining workflows, human annotation pipelines (see related pages).

Key concepts

- Slice: a workload partition (intent, tenant cohort, locale, prompt family) defined in the probe registry.
- Sentinel score: a composite signal combining fidelity delta, confidence calibration shift, and embedding drift (0-100).
- Quant hedging: automated rule set that routes a percentage of slice traffic to a higher-precision variant when sentinel score exceeds thresholds.
- Cost shield: per-slice budget to allow temporary hedging without blowing team-level cost targets.

Telemetry and metrics

Primary metrics (per slice, computed hourly):
- fidelity_delta_pct: relative drop in oracle-aligned metric (e.g., BLEU/QA-F1/Instruction-adherence) vs baseline (rolling 7d).
- topk_confidence_shift: change in average model token confidence or logit gap.
- embedding_drift_cosine: mean cosine distance between recent embeddings and baseline centroid.
- user_apdex_change: change in product Apdex correlated with quality signals.
- hedged_traffic_pct: percent of slice routed to higher fidelity.

Detection algorithm (high level)

1. Compute normalized z-scores for fidelity_delta_pct, confidence_shift, embedding_drift using slice historical window (90th percentile to reduce noise).
2. Sentinel score = weighted sum: 0.5*fidelity_z + 0.3*confidence_z + 0.2*embedding_z, clipped to 0-100.
3. Apply hysteresis: require sentinel score > threshold for 3 consecutive hourly bins before triggering hedging.
4. Raise severity levels: informational (20), guarded (40), hedging (60), immediate rollback (85).

Quant Hedging Policy (config example)

policy_name: slice_quant_hedge_v1
priority: high
thresholds:
  informational: 20
  guarded: 40
  hedging: 60
  rollback: 85
actions:
  guarded: notify-steward, increase-probe-frequency
  hedging: route-percent: 25; 50; 100 by step; duration: 2h-auto-evaluate
  rollback: immediate-shift-to-fp16, open-incident
cost_shield:
  default_monthly_credits_usd: 1500
  per_slice_max_pct_of_shield: 20
  auto-replenish_policy: manual

Policy semantics

- Hedging ramps are conservative: start with 25% traffic to higher-fidelity for 2 hours, evaluate fidelity_delta and user_apdex; if improved, escalate to 50% then 100%.
- Shielding prevents unlimited hedging: when a slice's cumulative hedging cost exceeds its allocated shield, the policy falls back to alert-only and requires steward approval.

Onboarding checklist for a new slice

1. Register slice in probe registry with owner, intent, and canonical prompt set.
2. Define baseline (rolling 14d) fidelity metric and target SLO.
3. Assign cost shield and steward approver.
4. Enable sentinel telemetry and probe frequency (default: 60 probes/hour).
5. Run synthetic shadow evaluation for 48 hours to collect initial embedding centroid.
6. Approve policy (slice_quant_hedge_v1) or provide overrides.

Runbook: when sentinel reports hedging trigger

1. Alerting: PagerDuty notify to slice steward, include sentinel diagnostics link and current metrics.
2. Triage steps (ordered):
   a. Review probe examples that contributed most to fidelity_delta (top 10 failing probes).
   b. Check config diff: model variant, tokenization, prompt-presets, quant profile.
   c. Inspect runtime errors and kernel fallbacks in last 2 hours.
   d. If hedging succeeded (fidelity_delta reduced by >= 40%), keep hedging and reduce probe aggressiveness after 12h.
   e. If no improvement, escalate to model-onboarding team for rollback to baseline model or retrain.
3. Communication: post a summary to the slice incident page and tag owners.
4. Post-incident: run regression-bisect playbook and create an action item with expected ETA.

CLI and API examples

- Query current sentinel score for slice 'enterprise-forms':
  curl -s -H 'Authorization: Bearer $REDWOOD_API_KEY' 'https://internal-api.redwood.ai/sentinel/v1/slices/enterprise-forms/score'

- Apply a temporary hedging override (requires steward token):
  curl -X POST -H 'Authorization: Bearer $STEWARD_TOKEN' -H 'Content-Type: application/json' -d '{"slice":"enterprise-forms","action":"hedge","route_percent":50,"duration_minutes":120}' https://internal-api.redwood.ai/sentinel/v1/overrides

Monitoring queries (prometheus-like pseudo)

- fidelity_delta_pct (1h avg) by slice:
  avg_over_time(fidelity_delta_pct[1h]) by (slice)
- sentinel_score recent:
  max_over_time(sentinel_score[3h]) by (slice)
- hedged_traffic_pct to detect cost pressure:
  sum(rate(hedged_traffic_pct[1h])) by (slice) > 0.15

Escalation and rollback criteria

- Immediate rollback: any slice with sentinel_score >= 85 and fidelity_delta_pct > 15% sustained for 1h.
- Steward approval required when hedging cost exceeds 50% of slice cost shield.
- Postmortem required if rollback occurred and customer impact > 5% of monthly queries.

Appendix: Example failure case

- Symptom: enterprise-forms slice shows fidelity_delta_pct = 22% and embedding_drift_cosine = 0.19; sentinel_score = 67.
- Automated action: hedge 25% -> 50% over 4h, fidelity_delta improved to 9% after 2h, hedging kept at 50% and steward notified.
- Outcome: no rollback, post-incident action to add targeted probes for form-parsing intent.
