Embedded inference positioning & CISO seller scripts

Overview
This document provides a concise, reproducible sales enablement package tailored for deals where customers evaluate embedded or private inference (VPC, on-prem, or dedicated capacity). It includes: positioning statements, competitive brief, pricing guidance examples, concise pitch scripts for technical and security stakeholders (CTO, Platform Eng, CISO), demo checklist, a short anonymized case study, objection handling, and a focused security FAQ for prospects.

Audience
- Account executives (AE) and sales engineers (SE) running discovery and technical validation calls
- Solutions architects preparing proposals for regulated or latency-sensitive customers
- Enterprise sellers negotiating reserved capacity and private deployment contracts

Key one-line messages (choose 1–2 per call)
- For Platform/Infra leads: "Deploy predictable, low-latency LLM inference in your VPC or on-prem with the same API and rollout controls you already use in hosted mode."
- For CTOs: "Reduce inference cost per meaningful token by combining quantization profiles, caching, and Redwood Optimize recommendations — without rebuilding your inference stack."
- For CISOs: "Keep data inside your network, retain full audit trails, and use your KMS while leveraging Redwood’s runtime optimizations and canary rollout controls."

Top value props (short bullets, use in sequence)*
- Predictable economics: reserved capacity + Optimize recommendations -> typical 30–60% unit cost reduction vs unmanaged self-hosted stacks for production workloads.
- Unified developer UX: same REST/SDK surface and rollout primitives across hosted, dedicated, and private.
- Production SLOs: configurable latency SLAs (p50/p95 targets) and automatic model-fallback policies.
- Security posture: customer-managed KMS/HSM, VPC peering/direct-connect support, detailed audit logs per token.

Pricing & packaging guidance (quick reference)
- Hosted (self-serve): per-token generation + embedding units. Best for trials and fast time-to-value.
- Dedicated (reserved capacity): monthly commitment; tiered pricing by GPU class and guaranteed throughput. Ideal when predictable latency and cost are required.
- Private (VPC / on-prem license): platform fee + support; optional professional services for initial packaging and air-gapped installs.

Objection handling cheat-sheet
- "We can just host it ourselves" → "Yes, but build vs buy tradeoff: Redwood removes repeated optimizations (KV caching, quantization profiles, kernel selection) and provides operational SLAs — all of which materially lower ongoing MTTI and ops cost. We’ll quantify the delta in the pricing appendix."
- "I’m worried about model drift and quality regressions" → "We surface per-prompt evals and regression alerts as part of Optimize; we can run initial guardrail evals on your production prompt set during a pilot."
- "Your hosted offering might see spikes" → "Use Dedicated + smart routing to ensure predictable throughput and configure fallbacks to lower-cost variants during regional outages."

Demo checklist (for SEs)
1. Confirm network path: VPN/VPC peering details and IP allowlist.
2. Validate auth flow: KMS key access patterns and service principal setup.
3. Show identical API call in hosted vs private (curl example).
4. Run a 1k-token workload to demonstrate p95 latency and KV caching impact.
5. Show audit log entry for the request and where it appears in the Console.

Security FAQ (focused for CISOs, concise answers)
Q: Can we keep all inference data in our VPC?
A: Yes. Redwood Private and Dedicated options support VPC-only deployment and peering. No training data or logs are transmitted to Redwood’s hosted control plane unless you enable that integration.

Q: How does key management work?
A: You provide the KMS/HSM keys. Redwood integrates with customer-managed KMS (AWS KMS, GCP KMS, Azure Key Vault) or brings-your-own-HSM for on-prem installs. Keys never leave customer control.

Q: What does auditing and logging look like?
A: Audit logs include request metadata, model version, and route. Logs are delivered to your logging endpoint (S3, GCS, or SIEM) and we support configurable retention and redaction policies.

Q: Can you support air-gapped installations?
A: Yes. We have a validated on-prem packaging process and an air-gapped deployment plan (see /confluence/eng-private-deployments/onprem-packaging). Professional services required for initial installation.

Q: How do you prove compliance for sales cycles?
A: We provide an evidence bundle: architecture diagrams, SOC2 summary, encryption and key management statements, network diagrams, and a deployment checklist used by our delivery team.
