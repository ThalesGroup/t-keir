onboarding-credentialing-and-deprovision-playbook-2027

Overview
======

Purpose: This playbook defines the standardized process for issuing, validating, and revoking technical credentials for employees, contractors, and long‑term vendors at Redwood. It covers tool-level access, role-based entitlement mapping, timelines and SLAs, audit cadence, and escalation paths. The goal is to ensure new joiners are productive quickly while minimizing security risk and maintaining compliance with audit requirements.

Scope
-----
- Applies to employees, contractors, and approved third‑party integrators who require access to internal systems.
- Covers provisioning for cloud accounts (GCP, AWS), data stores (Snowflake), source control (GitHub), collaboration (Slack, Confluence, Jira), CI/CD (Buildkite/GitHub Actions), and observability (Datadog).
- Does not replace team‑specific onboarding content (see related pages).

Service Level Objectives
-----------------------
- Target: 90% of new joiners provisioned with baseline tooling within 48 business hours of official start date.
- Emergency expedited provisioning: within 4 business hours (requires manager + people‑ops approval).
- Monthly entitlement review: completed within first 5 business days of each month.

Ownership and Roles
-------------------
- People Ops: initiates provisioning workflows, verifies employment type, and coordinates training links.
- IAM/Cloud Admins (eng-infra): create cloud/service accounts, manage infrastructure roles, and run monthly entitlement audits.
- Security: approves high‑privilege requests, maintains deprovision checklist, and runs quarterly tabletop exercises.
- Hiring Manager: confirms role template, approves exceptions, and verifies access post‑onboarding.
- IT Helpdesk: issues hardware credentials (laptops, YubiKeys), handles SSO/Okta failures.

Baseline Access Tiers
--------------------
- Tier 0 — Directory & Comms: Okta SSO, Slack (standard channels), Confluence read/write, Google Workspace email/calendar. (All full‑time hires)
- Tier 1 — Engineering Contributor: GitHub (repo access per team), Buildkite/GHA runner tokens, dev‑GCP project, internal dev Snowflake read.
- Tier 2 — Data/Platform: Snowflake role with dataset access, managed GCP service accounts, Datadog metrics dashboards.
- Tier 3 — Privileged Admins: org‑level cloud IAM, Terraform service accounts, production Snowflake write; requires security review and quarterly revalidation.

Onboarding Provisioning Checklist (step‑by‑step)
------------------------------------------------
1. People Ops opens new hire ticket in Jira onboarding queue with start date and role template.
2. Okta invite is issued automatically by HRIS webhook; IT Helpdesk confirms 2FA device shipment (YubiKey or Authenticator).
3. People Ops assigns baseline training modules and shares team runbook.
4. IAM Admin applies role template to user in GitHub, GCP, Snowflake, and Datadog.
5. Manager verifies access: runs post‑onboarding validation checklist within first 2 business days.
6. People Ops closes the Jira onboarding ticket after confirmation.

Example CLI snippets (for infra owners)
--------------------------------------
- Create a GCP service account (example):
  gcloud iam service-accounts create redwood-dev-USERNAME --display-name="dev account for USERNAME"
- Grant IAM role:
  gcloud projects add-iam-policy-binding redwood-dev --member="user:USERNAME@redwood.ai" --role="roles/viewer"
- GitHub: add to team via org API (curl example):
  curl -X PUT -H "Authorization: token $GH_ADMIN" https://api.github.com/orgs/redwood/teams/eng/memberships/USERNAME

High‑Privilege Requests and Exceptions
-------------------------------------
- Any request for Tier 3 access must be submitted through the privileged request form (Confluence > forms > privileged‑access) and include: business justification, duration, expected resources, and manager sign‑off.
- Approvals required: manager, security, IAM admin.
- Access is time‑boxed by default (max 90 days) and requires re‑application for renewal.

Deprovisioning (Offboarding and Role Changes)
---------------------------------------------
- Trigger: HR termination event or role change in HRIS triggers a webhook that opens a deprovision Jira ticket.
- Immediate actions (within 4 hours of ticket): suspend Okta session and remove active SSO tokens.
- Standard removal (within 24 hours): revoke GitHub org membership, remove GCP IAM bindings, disable Snowflake user, rotate shared credentials in team vaults.
- Hardware return: IT Helpdesk coordinates asset pickup/label return within 7 days.
- Audit log: IAM Admins supply a deprovision report to Security and People Ops within 3 business days.

Deprovision timeline summary:
- Suspend SSO: 0–4 hours
- Revoke system access: 4–24 hours
- Rotate team secrets and update vault: 24–72 hours
- Complete asset recovery: 7 days

Audit, Reporting, and Revalidation
----------------------------------
- Monthly entitlement review: People Ops + IAM run a de‑duplicated report and send anomalies to managers for remediation.
- Quarterly privileged access review: Security conducts a manual review of Tier 3 accounts and enforces removal or re‑approval.
- Annual penetration testing and access controls evaluation integrated into compliance calendar.

Escalation and Incident Handling
-------------------------------
1. If credentials are compromised, the user must report to security@redwood.ai and people‑ops immediately.
2. IAM Admins will revoke SSO and rotate any affected service accounts within 1 hour of confirmed compromise.
3. Post‑incident: tabletop with manager, People Ops, Security, and affected team within 3 business days.

Exception Handling and Temporary Overrides
-----------------------------------------
- Temporary overrides (e.g., contractor needing Tier 1 for 2 weeks) use the short‑lived access flow: privileged request form + manager approval + auto‑revocation timestamp.
- Security may grant an emergency access token with specific IP restrictions and audit logging enabled; requires post‑hoc justification.

Training and Manager Checklist
-----------------------------
Managers must:
- Confirm role template in the onboarding ticket before start date.
- Validate key accesses within 48 hours of start.
- Schedule the new hire for role‑relevant training modules in week 1.
- File any exceptions in the onboarding ticket and follow up within 7 days.

Common FAQs
-----------
Q: Who issues YubiKeys?
A: IT Helpdesk issues YubiKeys (or enrollment for authenticator) as part of Okta onboarding. Contact it-helpdesk@redwood.ai for expedited shipments.

Q: How long until I get access to production?
A: Production access is intentionally slow: expect 5–10 business days plus security review for Tier 3 access. Plan accordingly.

Q: What if my manager changes my access template?
A: Any change must go through the Jira access change flow; temporary access will be time boxed and require revalidation.
