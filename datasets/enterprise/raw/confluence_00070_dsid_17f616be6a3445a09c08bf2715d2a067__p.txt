Permissioning and Procurement Lifecycle Patterns

Overview

This page describes a compact, company-wide set of patterns and templates for: access & permissions, lightweight change management, data classification and handling, procurement & expenses, vendor onboarding, and travel approvals. The goal is to provide reproducible, low-friction flows that meet security and finance controls while minimizing friction for product and platform teams.

Principles (high level)
- Least privilege by default; temporary elevation when necessary.
- Single, auditable approval path for spend and access changes.
- Separation of duties between requestor, approver, and implementer.
- Risk-based variance: low-risk changes follow a lightweight path; high-risk changes get formal review.
- Templates and automation reduce clerical errors and speed approvals.

Scope
- Applies to all Redwood employees, contractors, and vendor integrations.
- Covers: account-level permissions, service/role grants, infrastructure change requests, data access and handling, procurement and vendor onboarding, travel and expense reimbursements.

Quick reference: ownership and SLAs
- Access Requests: owner_team = people-ops; SLA for standard requests = 2 business days.
- Elevated Privilege (temporary): owner_team = security; SLA = 4 business hours for urgent, 24 hours otherwise.
- Infrastructure Change Requests: owner_team = eng-platform; change validation window = 3 business days for non-urgent.
- Procurement Requests < $5k: owner_team = finance-legal (delegated approvers); SLA = 48 hours.
- Procurement Requests >= $5k: owner_team = finance-legal; requires manager + finance approval; SLA = 5 business days.

Roles and RACI (text table)
- Requestor: person initiating the request.
- Approver: manager or role-specific approver (see approval matrix).
- Implementer: engineer/admin performing the change.
- Reviewer/Auditor: security or finance reviewer for high-risk items.

Approval matrix (summary)
- Access:
  - Org-level or admin roles: Manager + Security review.
  - App-level read-only: Manager.
  - Service principal/automation keys: Security + Eng-platform.
- Spend:
  - <= $500: Manager.
  - $501–$5,000: Manager + Finance delegated approver.
  - > $5,000: Manager + Finance + Procurement lead.
- Vendor onboarding: All vendors with access to sensitive data require Security + Legal sign-off.

Access request flow (recommended lightweight pattern)
1) Requestor submits an Access Request using the ACCESS REQUEST template (link in templates section). Include reason, duration (if temporary), and resource.
2) Automated validation checks (IAM policy, resource tags, existing grants).
3) Manager receives approval email + one-click approve/deny.
4) If approval granted and role is standard, system auto-applies role and records audit event. If temporary, auto-expiry ticket created.
5) Security is notified for elevated roles or unusual patterns (out-of-band notification).
6) Requestor receives confirmation with audit ticket ID.

Change management (lightweight pattern for infra and config changes)
- When to use this pattern: routine configuration updates, non-invasive infra adjustments, runtime parameter tweaks.
- Minimal required artifacts: short description, impact analysis, rollback plan, scheduled window.
- Flow:
  1. Create a CHANGE REQUEST (CR) in the Change Tracker with: title, owner, change window, rollback steps, and validation checks.
  2. Automated linting checks: CI config, Terraform plan diff, linter output.
  3. Approvals: Manager + Eng-platform for infra; Manager + Security for security-affecting changes.
  4. Implementer executes change during scheduled window.
  5. Post-change validation: smoke tests, metrics (latency/error thresholds), and a 1-hour monitoring watch.
  6. Close CR with links to deployment logs and verification artifacts.
- High-risk changes: require a 3-day review and a canary deployment with rollback triggers.

Data classification and handling summary
- Classification tiers: PUBLIC, INTERNAL, CONFIDENTIAL, RESTRICTED.
- Handling rules (short):
  - PUBLIC: No controls required.
  - INTERNAL: Use company accounts; avoid sharing outside Redwood without approval.
  - CONFIDENTIAL: Encrypted at rest and in transit; access on a need-to-know basis; logged.
  - RESTRICTED: Strictly limited to named individuals/roles; key management with KMS/HSM; contractually controlled.
- Examples:
  - Customer PII: CONFIDENTIAL or RESTRICTED depending on contractual terms.
  - Model weights + sensitive prompts: CONFIDENTIAL (treated as IP).
  - Audit logs: INTERNAL (retention per policy).

Procurement and vendor onboarding (concise lifecycle)
- Pre-qualification checklist for vendors:
  - Business need justification and estimated annual spend.
  - Security posture summary: SOC2 or equivalent, encryption at rest/in transit, subprocessor list.
  - Privacy terms and DPA if processing customer data.
  - Insurance and indemnity (where applicable).
- Onboarding flow:
  1. Requestor opens a PROCUREMENT REQUEST with cost center, estimated spend, contract term, and vendor security info.
  2. Finance validates budget and assigns spend code.
  3. Legal or finance triggers Vendor Intake if the vendor handles regulated data.
  4. Procurement lead negotiates terms (if > $5k or non-standard).
  5. Contract signed, vendor record created, and bill-to/PO details stored.
- Vendor recurring review cadence: annual for production vendors, biennial for low-risk SaaS.

Expenses and travel (policy highlights)
- Employees should use corporate card when available; otherwise submit EXPENSE REPORT within 10 business days.
- Per diem and limits:
  - Domestic travel lodging: up to $300/night unless pre-approved.
  - International lodging: submit estimated cost; finance will review for reasonableness.
  - Meals: up to $75/day.
  - Ground transportation: ride-share or taxi; rental car requires prior manager approval.
- Travel approval flow:
  1. Employee creates a TRAVEL REQUEST with destination, dates, estimated cost, and business justification.
  2. Manager approves or requests changes.
  3. Finance may require additional approval for international travel or costs > $2,500.
  4. After travel, submit receipts and expense report.

Templates (examples and machine-friendly snippets)
- ACCESS REQUEST template (fields): requestor, resource, role, justification, duration, manager, impact, related_ticket.
- CHANGE REQUEST template (fields): title, owner, change_window, impact_summary, rollback_plan, risk_level, approvers, validation_checks.
- PROCUREMENT REQUEST example (YAML):
  requestor: "name@redwood.com"
  vendor: "Acme Vector"
  estimated_annual_spend: "$3,200"
  contract_term_months: "12"
  cost_center: "platform-research"
  security_posture: "SOC2 Type II"
  business_justification: "GPU monitoring and alerting for runtime"
  approvers: ["manager@example.com","finance@example.com"]

- EXPENSE REPORT example (JSON):
  {
    "employee": "name@redwood.com",
    "trip": "SFO-SEA 2025-02-10",
    "items": [
      {"type": "lodging", "amount": "275.00", "currency": "USD"},
      {"type": "meals", "amount": "45.00", "currency": "USD"}
    ],
    "total": "320.00"
  }

Operational controls and automation suggestions
- Integrate access requests with the IAM system (SCIM/OKTA) to auto-provision standard roles.
- Enforce temporary tokens for elevated access via a Time-Bound Elevation service with automatic revocation.
- Automate procurement threshold checks and route to the appropriate approvers.
- Store vendor artifacts (contracts, SOC reports) in a central, versioned repository and link them in the vendor record.

Escalation and exceptions
- Exception handling: submit an EXCEPTION REQUEST with rationale and compensating controls.
- Escalation path for blocked approvals:
  - Day 0–2: Manager follow-up.
  - Day 3–5: Owner_team lead engages.
  - After Day 5: Head of People-ops or Finance engages depending on domain.

Appendix A: Example vendor onboarding checklist (short)
- Business justification and owner.
- Data handling: does vendor process customer data? (yes/no).
- Contract status: DPA required? (yes/no).
- Security artifacts: SOC2 / penetration test summary.
- Insurance certificates.
- Assigned account owner and billing code.

Appendix B: Common Q&A
- Q: Who can request admin-level access?
  A: Any employee can request admin-level access, but approval requires manager + security and a documented business justification.
- Q: How long do temporary elevations last?
  A: Default = 8 hours. Requests for longer duration require manager & security approval.
