CI GPU interference profiling and synthetic benchmark harness

Summary

This page documents the CI-integrated GPU interference profiling harness and synthetic benchmark suite used to characterize noisy-neighbor effects across heterogeneous GPU pools. It describes the architecture, test catalog, Terraform/CI integration examples, actionable runbook steps for triage, and rollout guidance. The goal is to make interference reproducible, measurable, and automatable in our CI/GitOps pipelines so capacity and placement decisions are evidence-driven.

Scope

- Applies to all inference and eval CI lanes that allocate shared GPU pools (ephemeral and warm pools).
- Targets heterogenous fleets (A100, H100, L40) and mixed-precision kernel rollouts.
- Not a billing / chargeback spec — this focuses on technical profiling and scheduling inputs.

Motivation

We observe intermittent latency and throughput variance when tenant workloads co-locate on the same host, particularly for prefix-heavy inference and KV-cache-intensive jobs. This harness has three purposes:

1. Reproduce interference under controlled traffic mixes.
2. Instrument and capture signals (PCIE errors, SM util skews, power/thermal throttling, memory bandwidth counters).
3. Gate CI changes (kernel rollouts, quantized runtime builds, topology-aware autoscalers) with deterministic experiments.

Architecture overview

- Harness controller: "interf-harness" service (lightweight controller that schedules synthetic workloads and coordinates telemetry collection).
- Workload runners: container images (bench-runner:audit-v1) that implement synthetic inference load (tokenised FFN hotpaths, KV cache priming, tensor-concat stressors).
- Telemetry collector: sidecar + eBPF probes + perf counters shipped to telemetry pipeline (inference-metrics).
- CI integration: Buildkite / GitHub Actions steps that start ephemeral GPU nodes via Terraform and execute a canonical experiment matrix.

Test catalog (reference)

| Test id | Workload profile | Primary stressor | Typical run (s) | Purpose |
|---------|------------------|------------------|-----------------|---------|
| IF-PRX-1 | Short prefixes (avg 16 tokens) | KV-cache churn + small batch lat | 300 | Capture latency tail under prefix-heavy routing
| IF-BULK-4 | Large sequence generation (seq 2048) | SM compute saturation | 900 | Measure throughput variance and kernel selection impact
| IF-MEM-2 | Memory-bandwidth heavy (attention-only) | PCIe+DRAM bandwidth | 600 | Detect NUMA/PCIe interference hotspots
| IF-MLP-3 | FFN stress (mixed precision) | FP16 kernel divergence | 450 | Gate quantized kernel rollouts

Runbook: reproducing interference locally

1. Provision ephemeral infrastructure (dev sandbox):
   - terraform -chdir=terraform/ephemeral apply -var="pool=dev-ephemeral" -auto-approve
2. Start harness controller: kubectl -n infra apply -f manifests/interf-harness-deployment.yaml
3. Launch target experiment: kubectl -n infra exec deploy/interf-cli -- run --test IF-PRX-1 --duration 300 --sample-label=jenkins-local
4. Collect telemetry: kubectl -n observability exec -it deploy/tlm-collector -- fetch --run=latest --type=perf,ebpf,host-sensors > /tmp/interf-artifacts.tgz
5. Interpret key signals: look at pcie_retries, sm_util_percentile_95, mem_bw_util_95, power_cap_events. If pcie_retries > 1/min, escalate to network-gpu-oncall.

CI integration: canonical pipeline steps

- Stage 1: build bench-runner image and publish to registry:
  - make bench-image VERSION=${BUILDKITE_BUILD_NUMBER}
  - docker push $REGISTRY/bench-runner:${VERSION}
- Stage 2: terraform plan/apply ephemeral nodeset (with spot fallback knobs):
  - tf_workflow apply -var=ci_run=true -var=image=${VERSION}
- Stage 3: run matrix (parallel jobs across driver/kernel variants):
  - buildkite step matrix: 
    - kernel: [stock, quantized-canary] 
    - topology: [single-host, spread] 
- Stage 4: collect artifacts and publish a structured summary JSON to the CI artifact store.

Gating rules (example)

- Latency tail (IF-PRX-1 p99) must not regress > 15% versus baseline for canary to pass.
- Throughput (IF-BULK-4 mean tokens/sec) must be within -10%..+5% of baseline.
- If any HW telemetry shows power_cap_events or pcie_retry spikes, the pipeline fails automatically.

Terraform / IaC module example

The harness uses a small Terraform module to create ephemeral GPU node pools and to label nodes for topology tests. Example snippet:

module "ephemeral_gpu_nodes" {
  source = "git::ssh://git@repo.redwood.ai/infra/terraform//modules/ephemeral_gpu_pool"
  name   = "ci-interf-${var.run_id}"
  region = var.region
  gpu_type = var.gpu_type # e.g., a100, h100
  count = var.count
  labels = { "bench-interf" = "true" "ci-run" = var.run_id }
  spot_fallback = true
}

Notes and constraints:
- Module sets preemptible/spot with a two-tier fallback: exact SKU -> SKU family -> on-demand.
- Provisioner attaches RBAC role gpu:harness-runner so CI jobs can create node leases.

Telemetry and metrics (what we capture)

| metric | source | alert threshold (example) | retention |
|--------|--------|--------------------------|-----------|
| p99_latency_ms(IF-PRX-1) | inference-metrics | > baseline*1.15 => FAIL | 30d |
| tokens_per_sec(IF-BULK-4) | inference-metrics | < baseline*0.9 => FAIL | 30d |
| pcie_retries_per_min | node-exporter + eBPF | > 1/min => Investigator alert | 14d |
| sm_util_95 | nvml/perf | delta > 20% between colocated tasks => Investigate | 14d |

Interference triage checklist

1. Confirm experiment reproducibility: rerun with different seed and host spread option.
2. Check node health: nvml-smi output, dmesg for GPU errors, firmware version mismatches.
3. Verify PCIe topology: run pci-topology.sh and compare against the topology baseline table.
4. Reproduce with isolation: run each workload on a dedicated host to confirm with/without delta.
5. If persistent, capture full perf profile and open an internal ticket with label "gpu-interference" including artifacts.

Ownership and escalation

- Primary owner: infra-performance team (pager: infra-perf on-call).
- Secondary owner: gpu-runtime team (pager: gpu-runtime on-call).
- Escalations: if hardware telemetry indicates ECC errors or machine stability issues, immediately page platform-hardware and stop any CI provisioning to that region.

Rollout checklist for kernel / quantization canary

1. Run baseline matrix on stock runtime and store canonical baselines in S3 (/bench-baselines/{date}).
2. Enable canary kernel on 5% of CI ephemeral nodes (topology: spread).
3. Execute 3 consecutive matrix runs across the week during low-traffic window.
4. Compare automated summaries; if any gating rule is violated, auto-fail the canary and open an RCA ticket.

.manifests/interf-harness-deployment.yaml (summary):
apiVersion: apps/v1
kind: Deployment
metadata:
  name: interf-harness
spec:
  replicas: 2
  template:
    spec:
      containers:
      - name: harness
        image: registry.redwood.ai/bench-runner:latest
        env:
        - name: TELEMETRY_ENDPOINT
          value: https://ingest.redwood.ai/inference-metrics

Governance and data retention

- Baseline snapshots (S3) are versioned and immutable once published for a release window.
