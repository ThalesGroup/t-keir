This document provides a compact, hands-on set of playground labs, SDK integration templates, API examples, and canonical error-injection recipes intended for developer onboarding, SDK maintainers, and support engineers. 1) Quickstart labs (local)
Overview: Each lab is runnable in under 10 minutes on a developer workstation. The labs assume a Redwood API key available in REDWOOD_API_KEY and Docker (for the local proxy) if you want to simulate network faults. Use the sandbox token (org-sandbox) for functional testing only.

Lab A: Auth + Simple Generation
- Objective: Validate SDK credential handling and error semantics.
- Steps:
  1. Install: pip install redwood-sdk==0.6.0 (or npm i @redwood/sdk@0.6.0)
  2. Set credentials: export REDWOOD_API_KEY="sk-sandbox-xxxx"
  3. Run example: python examples/auth_gen.py
- Expected output: JSON with tokens_used, model_name, and a 200-level response.
- Failure injection: run with REDWOOD_API_KEY="" to verify 401 handling and telemetry breadcrumbs.

Lab B: Streaming and Resume Simulation
- Objective: Validate partial responses and resume semantics used by front-end clients.
- Steps:
  1. Start local stub: docker run -p 8080:8080 redwood/local-runtime-stub:0.4
  2. Run node streaming example: node examples/stream_resume.js --url http://localhost:8080
  3. Kill the process at token 60 and run again to validate idempotent resume.
- Failure injection: use tc/netem to add 200ms packet loss on loopback.

Lab C: Batching + Local Prefetch Cache
- Objective: Measure latency and unit cost impact of local prefetch + batcher.
- Steps:
  1. Start the batcher: ./bin/local-batcher --config examples/batcher.yaml
  2. Run the load script: python examples/batch_load.py --qps 20 --dur 60
  3. Inspect metrics: curl http://localhost:9100/metrics | grep redwood_batch_latency
- Expected thresholds: p95 < 120ms with batch size <= 8; cost/token reduced by ~18% when cache hit ratio >= 0.6

2) API examples (copiable)
Curl: single-shot generation
```
curl -X POST https://api.redwood.ai/v1/generate \
  -H "Authorization: Bearer $REDWOOD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"redwood-small-2026","input":"Summarize the following..."}'
```
Python (requests): streaming w/ reconnect logic
```
import requests
from requests.exceptions import RequestException

URL = "https://api.redwood.ai/v1/stream"
headers = {"Authorization": f"Bearer {os.environ['REDWOOD_API_KEY']}"}
try:
  r = requests.post(URL, json={"model":"redwood-small-2026","input":"..."}, stream=True, timeout=30)
  for line in r.iter_lines():
    if line:
      print(line.decode())
except RequestException as e:
  # canonical retry backoff for SDKs: 100ms, 500ms, 1s
  print("retrying", e)
```
Node (sdk snippet): resumable stream + telemetry event
```
const Redwood = require('@redwood/sdk')
const client = new Redwood({ apiKey: process.env.REDWOOD_API_KEY })
const stream = client.stream({ model: 'redwood-small-2026', input: '...' })
stream.on('data', chunk => console.log(chunk))
stream.on('closed', () => client.telemetry.event('stream.closed'))
```

3) SDK template layout and recommended config
Purpose: A baseline SDK layout that reduces onboarding time for new language SDKs.
Recommended file layout:
- /src/index.js or /src/__init__.py (public entrypoint)
- /examples/* (playground snippets)
- /test/golden/* (integration goldens e2e-lite)
- /docs/snippets/* (extracted snippets for docs site)
- /scripts/ci/* (smoke harness)

Minimum config table:
| setting | description | recommended default | owner |
|---|---|---:|---|
| batcher.max_size | max queued requests per batch | 8 | sdk-team |
| retry.backoff_initial_ms | initial backoff on 5xx/timeout | 100 | sdk-team |
| telemetry.level | snapshot vs full | snapshot | devx-team |
| local_cache.ttl_seconds | ephemeral prefetch TTL | 30 | devx-team |
| snippet.auto_sync | copy examples into docs site on release | true | docs-engineering |

4) Docs site operating procedure (snippets and releases)
This section defines how snippet changes are validated and released to the docs site to avoid regressions.
Checklist for snippet or quickstart updates:
1. Update snippet in /docs/snippets with a runnable marker and include a smoke test under /test/golden that completes inside CI (30s wall).
2. Open PR with label docs:snippet and request reviewers from devx and sdk teams.
3. CI must pass both unit + golden smoke. Golden run must post a synthetic telemetry event to the staging snippet-harness.
4. Docs release steps (owner: docs-engineering):
   a. Merge PR after approvals.
   b. Run docs-site preview pipeline and verify snippet rendering at https://docs-staging.redwood.ai/snippets/<slug>
   c. Create release note in product-docs/release-notes referencing snippet id.
   d. If change modifies API surface, a feature flag must be set and a 2-week deprecation notice posted on SDK CHANGELOG.
Emergency rollback (if snippet causes production SDK break):
1. Revert merge in the docs repo.
2. Create a Patch release for the SDK with the old snippet embedded as a fallback comment.
3. Notify support and post incident note in #devx-snippet-incidents.

5) Top support issues and canonical fixes
A compact list of recurring issues observed in support tickets, with triage steps and canonical fixes. Use these as the first-pass checklist when assembling a support bundle.

Issue: Authentication failures (403/401)
- Symptom: sudden spike of 401s from a single tenant after a regional failover.
- Quick triage:
  1. Verify token expiry: echo $REDWOOD_API_KEY | cut -d'.' -f2 | base64 --decode || (note: some tokens are opaque)
  2. Check request timestamps vs server logs: curl "https://logs.redwood.ai/query?tenant=...&from=now-15m" -H "Authorization: Bearer $AUDIT_TOKEN"
- Canonical fix: Confirm token rotation window was applied; if rotated mid-deploy, advise client to use retry with 429/401 handshake: 1) fetch new token, 2) replay idempotent requests.

Issue: Streaming partial payload stops mid-response
- Symptom: Front-end sees stream close at ~50–80 tokens with no finalization event.
- Quick triage:
  1. Collect client side socket logs and server stream-ids: identify last sequence id.
  2. Correlate with runtime instance (X-Instance-ID header) and check instance health (systemd logs, OOM).
- Canonical fix: In SDKs implement resumable sequence-id resume: send last_ack and resume_token; if resume fails, fall back to retriable deterministic regeneration with a note in telemetry.

Issue: Batcher latency spikes at p95
- Symptom: p95 latency for generation increases by >200ms after traffic shift.
- Quick triage:
  1. Inspect batch size distribution: curl http://batcher-host:9000/debug/batches
  2. Check cache hit ratio: curl http://local-cache:9119/metrics | grep cache_hit_ratio
- Canonical fix: Reduce max window to 50ms for latency-sensitive routes and promote local cache prefetch for the affected route. Add an autoscaling policy for batcher pool if sustained QPS over commit.

6) Metrics, ownership, and lifecycle
- Runtime for docs updates: docs snippets should be validated weekly in a Golden CI job. Failing snippets generate a pager during business hours only.
- Owners:
  - SDK snippets: devx-sdks (primary), sdk-team (secondary)
  - Streaming examples: eng-serving-runtime (primary), devx-sdks (secondary)
  - Docs publishing pipeline: docs-engineering (primary)
- KPIs to track:
  - snippet_runnable_rate (goal 98%)
  - mean_time_to_fix_snippet_broken (target < 48 hours)
  - support_escalation_rate_due_to_snippets (target < 2%)

Appendix: Useful commands and debugging snippets
- Collect support bundle (local):
  tar czf support-bundle-$(date +%s).tgz logs/*.log metrics/*.prom diagnostics/*.json
- Simulate 10% packet loss locally (Linux):
  sudo tc qdisc add dev lo root netem loss 10%
- Canonical script to replay a failed request with idempotency key (bash):
  curl -X POST https://api.redwood.ai/v1/replay -H "Authorization: Bearer $REDWOOD_API_KEY" -d '{"idempotency_key":"<key>","original_request":{...}}'
