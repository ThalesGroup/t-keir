Incident Review: Tool-call argument JSON malformed in streaming (us-east)

## Summary
On 2025-02-12, a configuration canary in us-east introduced malformed JSON in tool/function calling arguments for a small subset of streaming requests. At least one dedicated customer escalation (HelioPay) reported strict JSON parsing failures.

## Customer impact
- Symptom: `tool_calls[].arguments` contained trailing commas or invalid escaping
- Primary impact: customer tool router failed to deserialize arguments; resulted in request retries and error spikes
- Affected: streaming-enabled tool calls with arguments spanning multiple deltas

## Detection
- External: customer escalation via Support (SUP-1842)
- Internal: increased 5xx rate in a dedicated tenant route; no automated alert existed for JSON validity

## Timeline (UTC)
- 2025-02-10 23:00: canary enabled `tool_args_delta_coalesce_v2` in us-east
- 2025-02-12 15:10: customer escalation reported malformed JSON
- 2025-02-12 16:05: rollback of `tool_args_delta_coalesce_v2` completed
- 2025-02-13 09:00: CS published workaround guidance

## Root cause
The streaming delta coalescer appended separators when joining tool-call argument fragments and did not correctly handle the end-of-object boundary when a fragment ended with a comma token. This produced an extra comma immediately before `}` in rare chunk boundary cases.

## Mitigation
- Rolled back the canary flag in us-east
- Provided customer workaround guidance (disable streaming for tool calls; validate + retry)

## Corrective actions
1. Add end-of-tool-call JSON validation in the serializer path
2. Add metric: `tool_args_json_valid_rate` per region/model
3. Add alert when valid rate < 99.9% for 15 minutes
