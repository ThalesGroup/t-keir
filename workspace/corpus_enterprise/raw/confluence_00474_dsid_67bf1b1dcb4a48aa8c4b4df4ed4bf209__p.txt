Prefetch Experiment Validation Cookbook

h1. Prefetch Experiment Validation Cookbook

Summary

This page is a pragmatic cookbook for designing, validating, and operating experiments that change prefetch / warmset behavior in the runtime (service names: runtime-prefetcher, platform-allocator). It condenses lab procedures, telemetry recipes, safe-canary steps, rollback actions, and a lightweight retrospective template so teams can run experiments with predictable operator overhead and clear success criteria.

Scope

- Applies to any change that affects proactive KV/prefix caching, warmed attention states, or warmset sharding in the runtime.
- Intended audience: platform operators, runtime-affinity engineers, SRE, and product owners running cost/latency experiments.
- Not in scope: model-architecture changes, customer-visible prompting logic, or access-control modifications. Follow the security playbooks for those.

Primary objectives

- Confirmed cost-per-token reduction or operator-validated latency improvement without SLO regressions.
- Reproducible experiment wiring (config, flags, cohort tags).
- Operator-safe rollback and rapid mitigation runbook.

Acceptance criteria (must be explicit before full rollout)

- Token-cost: measured cohort token_cost_delta <= -6% (two-hour stable window)
- Latency: cohort p99 foreground latency increase <= 5% absolute versus baseline; p95 increase <= 3%
- Errors: cohort HTTP error-rate delta <= +0.05% absolute
- Quality: no model-quality score drop > 0.015 on the canonical prompt-sets for the cohort

Terminology

- prefetch/warmset: proactive loading of KV or attention state to reduce initial-token latency.
- cohort: tenant set / route group assigned to an experiment (e.g., small-chat-cohort).
- baseline: the last stable configuration before experiment changes were applied.

Pre-flight checklist

1) Experiment config exists and is feature-flagged (feature flag name: ff.prefetch.<exp-id>).
2) Lab validation complete for target model families and sequence-length distributions.
3) Grafana dashboard and Prometheus alert bundle created and reviewed.
4) Operator on-call notified with a pre-roll contact list and runbook link.
5) Security and SRE sign-off for cohorts that include regulated or restricted tenants.

Lab validation recipe

1. Environment and naming
   - Create an isolated lab cluster: runtime-lab-<team>-<exp-id>.
   - Use a reproducible experiment id: exp-prefetch-<YYMM>-<short>.

2. Representative workloads (minimum set)
   - short-chat: median sequence <= 128 tokens, high-turn-rate
   - long-chat: median >= 512 tokens with KV-dominant reuse patterns
   - embedding/similarity bursts: high QPS, small response sizes

3. Configuration snippet (YAML) - store under experiments/exp-prefetch-<id>/experiment-config.yaml:
   prefetch:
     enabled: true
     strategy: cohort-window
     window_ms: "125"
     max_prefetch_kb: "256"
     prefetch_budget_tokens: "10000"
     experiment_id: "exp-prefetch-2509-smallchat"

4. Warmup and stability runs
   - Warmup: 3x 10-minute runs for kernel/JIT stabilization.
   - Validation: run each workload for >= 2 hours with stable QPS (traffic-replayer) and capture full metric set.

5. Data collection and post-processing
   - Export raw traces, prefix cache logs, and kernel-switch counters.
   - Produce a validation report with: baseline vs experiment deltas, memory pressure, kernel-restarts, and model-quality scores.

Telemetry and dashboards (must-have panels)

Create Grafana folder: /dashboards/prefetch/exp-<id> and include at minimum:
- Token cost per minute (token_cost.sum / minute) split by tenant/cohort
- Prefix cache hit ratio (prefix_cache.hits / prefix_cache.requests) by cohort
- Foreground request latency histogram (p50/p95/p99) by cohort
- Kernel/jit swap events (runtime.kernel.switches) and restarts per-minute
- Memory pressure: gpu_mem.used / gpu_mem.total and per-pool breakdown
- LLM prompt-set quality score delta (llm_eval.prompt_set_score.delta)
- Error rate and upstream model-failure rate
- SLI: SLO success percentage (latency+error combined)

Suggested alert rules (examples)

- Prefetch_High_Error_Rate:
  expr: increase(http_errors_total[5m]) > 0.1 * increase(http_requests_total[5m])
  for: 3m
  severity: P1
  runbook: emergency rollback section (below)

- Prefetch_P99_Regression:
  expr: (histogram_quantile(0.99, sum(rate(foreground_request_latency_bucket[5m])))) > (baseline_p99 * 1.05)
  for: 5m
  severity: P2
  runbook: investigate and consider rollback

Cohort selection and sizing guidance

- Start narrow: homogeneous model family, consistent sequence-length distribution.
- Initial canary: <= 2% tenants OR <= 10 tenants (whichever is smaller).
- Exclude enterprise/regulatory tenants until experiment is validated at 25% rollout.
- Annotate tenant metadata: tenant.metadata.prefetch_experiment = <exp-id>

Canary and progressive rollout pattern

1) Canary step 0: synthetic-only canary in dedicated region (2 hours)
2) Canary step 1: 1-2 low-risk tenants, 0.5-1% traffic, 30-60 minutes
3) Ramp: 1% -> 5% -> 10% -> 25% with a hold of 2x SLO window (e.g., 2x24h for long-term effects)
4) Full rollout: after stable metrics at 25% for 24 hours and explicit operator approval

Rollback and emergency mitigation (operator runbook)

Immediate actions (within first 5 minutes)
- Flip feature flag off: curl -X POST https://flags.internal/ff.prefetch.<exp-id>/disable
- Run automated rollback job: ./allocator rollback --exp <exp-id> --region <region>
- Drain warmed shards for affected cohort: cache-drain --cohort <exp-id> --force
- Create incident channel: #inc-prefetch-<exp-id>-<region> and notify SRE and runtime-affinity

Post-rollback verification
- p99 latency returns to baseline within 5-10 minutes for affected tenants
- Token-cost deltas normalize within 30 minutes
- No residual kernel restarts at scale (monitor kernel.switches)

Safety gates and quality gating

- Quality gate: any model-quality score drop > 0.015 triggers automated hold and rollback.
- ACL gate: OPA policy prevents enabling for restricted tenants without security approval.
- Memory gate: if gpu_mem.used / gpu_mem.total increases > 12% sustained for 10 minutes, trigger P1 review.

Cost modeling and estimator tooling

- Use tools/prefetch_cost_estimator.py to estimate memory and token amortization:
  tools/prefetch_cost_estimator.py --cohort <exp-id> --qps 200 --avg-seq 128 --mem-per-prefetch-kb 32
- Record both amortized token-cost and peak GPU memory consumption in the validation report.

Artifact checklist (store in experiments/exp-prefetch-<id>/artifacts)

- experiment-config.yaml
- traffic-replay-seed-<v>.json and replay script version
- grafana-export/ (screenshots and raw panel JSON)
- prefetched-shard-mapping-<id>.csv
- validation-report-<id>.md (metrics, plots, conclusions)

Retrospective template (fill after run)

- Expectations: what we planned to change and why
- Outcome: metric deltas with time-series snippets and screenshots
- Root cause analysis: operator/system/model-level causes
- Action items: owner, due date, and acceptance criteria
- Follow-ups: additional lab experiments or engineering tasks (e.g., kernel tuning)

Quick commands (examples)

- Deploy experiment to lab:
  kubectl apply -f experiments/exp-prefetch-<id>/experiment-config.yaml -n runtime-lab-<team>

- Rollback (platform operator):
  ./allocator rollback --exp <exp-id> --region us-west-2

- Drain cohort cache shards:
  cache-drain --cohort <exp-id> --region us-west-2 --timeout 60s

- Start traffic replay for validation:
  traffic-replayer --seed replay-v3 --target runtime-lab-<team> --duration 120m --qps 150 --workload short-chat
