Kernel Priority Calibration Lab Notebook

Summary
-------
This lab notebook documents a sequence of controlled experiments to calibrate kernel-level priorities and credit assignments in the Redwood serving runtime. The objective is to produce a repeatable mapping from request traffic characteristics to scheduler priority/weight settings that meet our latency SLOs while minimizing cost and token-level variance.

Purpose and scope
------------------
- Purpose: Establish a defensible, observable calibration process for kernel priority settings used by kernel-manager and scheduler-coordinator.
- Scope: Experiments span the dedicated GPU pool (gpool-rt-prod-sim), the local experiment cluster (lab-gpu-01..04), and the shadow-routing infrastructure used by the performance lab. This notebook does NOT change production configuration; it defines candidate settings for canary rollout.

Background and motivation
-------------------------
Over the last 18 months we've observed recurring p95 tail spikes for small interactive chat workloads when mixed with long-running batch generations. Investigation shows credit starvation and kernel handoff delays in the dispatcher + kernel pipeline. This calibration aims to:
1) Quantify how per-request weight, kernel quantum size, and preemption granularity affect latency distribution.
2) Generate recommended rule sets for the priority expression language used by kernel-manager.
3) Provide an audit trail and artifacts (traces, kernel-profiles, sample payloads) for sign-off prior to rollout.

Key concepts and definitions
---------------------------
- Kernel: GPU execution unit as exposed by kernel-agent (e.g., attn-kernel-v2).
- Priority weight: numeric weight applied by scheduler-coordinator when allocating slot quantum.
- Quantum: minimal GPU time-slice unit in microseconds (default 2000us in lab).
- Preemption point: safe boundary (KV cache alignment) where kernels can be interrupted.

Testbed and baseline configuration
----------------------------------
- Hardware: 4 x A100-80GB (lab-gpu-01..04), NVLink disabled for determinism in early runs.
- Software: runtime v3.14.2 (branch: experiment/kernel-calibration), kernel-agent v2.7.0, dispatch-service v1.22.
- Telemetry: traces via trace-proxy -> jaeger-lab, metrics to prometheus-lab, payload capture persisted to s3://redwood-lab-artifacts/kernel-calib/2026-04.
- Baseline SLOs used in lab: p50 < 30ms, p95 < 120ms for short-chat profile; throughput target 400 reqs/s for medium packing.

Calibration procedure (step-by-step)
-----------------------------------
1. Prepare lab cluster: reboot lab-gpu nodes, disable NVLink, ensure kernel-agent v2.7.0 running.
2. Load baseline model: llama-compat-13b-int8 (tag: lab-2026-02) to isolate kernel behavior from model variance.
3. Deploy traffic generator (tg-runner) with recorded production short-chat and long-burst corpora. Command: 

   ./tg-runner --target lab-gateway:8443 --corpus corpora/short-chat.json --rps 320 --duration 900 --tag run-A

4. Apply priority profile via kernel-manager CLI (example):

   rwd-kernelctl set-profile --profile-name favor-short --rules "priority(expression='request.shape == \"short\" ? 3 : 1', preempt=true, quantum_us=2000)"

5. Collect telemetry: Ensure sampling via experiment-telemetry job. Key artifacts:
   - jaeger traces: trace-id prefix "calib-2026-04-A"
   - prometheus metrics: histogram rwd_kernel_latency_{quantile}
   - captured payloads: s3://redwood-lab-artifacts/kernel-calib/2026-04/run-A/

6. Run 1-hour trial, then a 6-hour steady-state for stability measurement.
7. Post-process: run analysis notebook /notebooks/kernel-calib-analysis.ipynb to compute p50/p95, fairness index, and variance.

Telemetry and measurement definitions
-----------------------------------
- Latency decomposition: request_total = frontend_queue + dispatch_delay + kernel_wait + kernel_exec + post_process. Each is traced and tagged.
- Fairness Index (FI): normalized Jain's index on per-cohort latency at p95 (goal >= 0.85).
- Kernel Utilization: GPU active seconds / wall-time (target 0.6-0.85 depending on workload).
- SLO thresholds: alert if burst p95 > 2x target or FI < 0.7.

Experiment logs (high level)
---------------------------
- Run A (2026-04-20): baseline run, observed p95=138ms (exceeded target). Notes: dispatcher queueing prominent. Trace set: calib-2026-04-A.*
- Run B (2026-04-22): favor-short, preemption enabled, p95=86ms, FI=0.82. Short requests improved; tails reduced but long jobs saw increased runtime by 6%.
- Run C (2026-05-03): smaller quantum (1000us) reduced tail by 12% but increased kernel dispatch overhead (extra context switches). Kernel exec variance up 8%.
- Run D (2026-05-18): conservative quantum for long jobs reduced throughput by 14% with negligible improvements to short p95.
- Run E (2026-09-07): dynamic-adaptive rule using recent-ten-second-load reduced peak p95 by 20% in burst scenarios; needs further stability testing.

Decision rules and acceptance criteria
------------------------------------
Use the following rule to accept a candidate profile into canary:
1. Candidate must achieve p95 <= 1.1 * lab SLO for three independent 6-hour runs under synthetic production-mix.
2. FI >= 0.8 across cohorts for the same runs.
3. GPU utilization not below baseline by more than 10% (to avoid wasteful idle capacity).
4. No increase in observed model inference errors (model failure rate <= baseline + 0.1%).

Troubleshooting checklist
-------------------------
- If p95 regresses after profile apply:
  1) Re-run short deterministic microbenchmarks (script: tools/microbench/kernel_probe.sh).
  2) Collect full jaeger traces with full payload sampling for 30m.
  3) If kernel wait dominates >60% of tail, revert profile and open ticket on #sre-runtime.

Observed side-effects and mitigation notes
----------------------------------------
- Smaller quantum increases context-switch overhead. Mitigation: only use quantum <= 1000us for sub-100ms expected executions.
- Aggressive preemption can increase cache thrash for models with large KV caches; avoid preemption for models with >60M KV footprint.
