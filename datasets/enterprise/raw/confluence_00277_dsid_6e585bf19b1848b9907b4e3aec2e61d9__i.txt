Inter-Region GPU Networking: Egress Cost Reduction, PrivateLink Patterns, and TLS Handling

Overview

This playbook describes recommended architecture patterns, IaC snippets, operational guardrails, and an emergency runbook for inter-region GPU traffic that drives high egress costs or creates TLS/MTU problems for long-running inference streams. It targets: Dedicated and Private NVIDIA/AMD GPU pools connecting across cloud regions, cross-account PrivateLink/VPC-connector patterns, and Terraform module considerations for safe rollouts.

Goals and non‑goals
- Goals:
  - Reduce cross-region egress spend while preserving latency and throughput for inference workloads.
  - Provide safe PrivateLink / service‑mesh pattern alternatives to wide-open peering where tenant isolation and compliance are required.
  - Define TLS termination guidance for streaming tokens/KV-cache traffic and how to handle path MTU and connection affinity.
- Non‑goals:
  - This document does not cover application-level model merging or model sharding approaches.

Key concepts and tradeoffs
- Egress vs Latency:  Cross-region PrivateLink (or Cloud Interconnect) can reduce public egress but may add hop/processing cost and require cross-account endpoints. Peering is lower operational latency but can increase blast radius and egress meter complexity.
- Batching and Prefix Caching: Increasing request batching or KV cache reuse is often the highest‑ROI egress reducer at the application layer; network changes are complementary.
- TLS termination points: Terminating TLS at a regional gateway lowers CPU cost on GPU nodes and enables per-route inspection/caching. End-to-end TLS improves compliance but complicates caching and may exacerbate MTU issues on tunnels.

Recommended architectures (patterns)
1) Regional Ingress + Central Model Serving with PrivateLink (recommended for regulated customers)
- Client -> Regional API gateway (TLS) -> Regional proxy (mutual TLS to central region endpoints via PrivateLink) -> Central GPU pool.
- Pros: minimal public egress, clear ownership per-account, fine-grained IAM.
- Cons: additional proxies and potential latency.

2) Multi-region model replicas with smart routing (recommended for latency-sensitive inference)
- Deploy model replicas closer to traffic, maintain a small set of canonical models in central pool for large/batch jobs.
- Pros: low tail latency, lower cross-region streaming.
- Cons: increased republish traffic and storage sync costs.

3) Transit gateway + selective egress controls (recommended for large-scale multi-account infra)
- Use Transit/Hub + route tables to centralize control. Apply egress NATs per-tenant and enforce quotas.
- Pros: central ops, simpler routing.
- Cons: single central control plane = operational risk.

Network and TLS guidance
- TLS termination options:
  - Terminate at regional gateway when you need to inspect requests for caching or drop malicious payloads. Use mTLS between gateway and GPU nodes.
  - Keep end-to-end TLS for PII/regulated payloads; combine with token-based caching by gateway to reduce repeated decryption on GPUs.
- Connection affinity and streaming:
  - Use sticky sessions or hash-based affinity for long-lived streaming sessions (server‑sent events / chunked responses) so KV caches remain hot.
  - Prefer long-lived TCP connections with HTTP/2 or gRPC multiplexing; avoid recreating TLS repeatedly.
- MTU and jumbo frames:
  - Validate path MTU on VPN/tunnel routes. Large model payloads + gRPC streaming can hit fragmentation thresholds.
  - Recommended: 1400–1450 MTU on tunnels if path MTU discovery is flaky; enable DF detection in test harness.

Terraform / IaC patterns (examples)
- Principle: Avoid hard-coded region-to-region IDs in modules. Provide data sources that resolve correct PrivateLink endpoint IDs per-account. Use feature flags to toggle between peering and privatelink patterns.

Example snippet (Terraform pseudo-template)
```hcl
module "gpu_network_endpoint" {
  source = "git::ssh://git@repo/internal-terraform-modules.git//privatelink-endpoint"

  region              = var.region
  service_name        = data.aws_vpc_endpoint_service.gpu_service.service_name
  allowed_account_ids = var.consumer_account_ids
  subnet_ids          = var.endpoint_subnet_ids
  tags = merge(var.common_tags, {component = "gpu-privatelink"})
}
```

- CI gating: Changes to privatelink modules must require a manual approval step in the pipeline when altering allowed_account_ids or route tables. See CI/CD section below.

Operational SLOs, metrics, and alert thresholds
- SLOs (example):
  - 95th percentile request tail latency for streaming inference <= 250ms region-local.
  - Cross-region egress cost per 1M tokens should not increase >10% month-over-month absent signed change request.
- Key metrics to export to observability:
  - network.egress_bytes_per_region (per-account, per-model)
  - network.egress_cost_estimate_per_hour (projected)
  - network.path_mtu_failures_total (per-tunnel)
  - connection.active_streams (per-node)
  - connection.stream_reconnect_rate (per-10m)
- Alert thresholds (examples):
  - network.egress_cost_estimate_per_hour > budget_rate*1.2 for 30m -> P2 paging to infra-finance oncall.
  - path_mtu_failures_total > 5 per 5m -> P1 paging to networking oncall.

Runbook: urgent egress spike (summary)
1) Detect: Pager triggers from billing-derived egress forecast alert.
2) Triage (5m): Identify top 5 (account, region, model) tuples by egress size using network.egress_bytes_per_region and query tracing.
3) Immediate mitigation (10m):
   - If PrivateLink exists: disable cross-region route propagation for the affected account via terraform toggle (see quick toggle below).
   - If peering used: remove route to expensive region and replace with reject route in Transit Gateway to force local fallbacks.
   - If neither, apply temporary token rate-limit config at regional gateway to cap requests to 10 rps per token.
4) Reduce application-level cost (15–60m): enable aggressive KV prefix caching on the gateway, increase batching window for non-interactive jobs, and re-route batch jobs to central bulk region with cheaper egress.
5) Postmortem: Create incident with cost delta analysis, deployment diffs, and retro within 7 business days.

Quick toggle example: terraform variable switch pattern
- Implement a guard variable in a small ops-only Terraform repo that flips routing from peering to blackhole for a region and is guarded by a PR that requires 2 approvers: ops_lead and finance_lead.

Operational runbooks and playbooks (short list)
- Daily checks for steady-state:
  - Top 10 accounts by egress (rollup) and delta vs baseline.
  - Path MTU probe results for all VPNs, flag failures.
- Weekly tasks:
  - Validate PrivateLink endpoint health and rotate endpoint policies in test accounts.
  - Reconcile route tables and remove stale entries older than 90 days.

Governance and ownership
- Ownership:
  - Network & Cloud Accounts Team: default owner for PrivateLink/peering configurations and Transit Gateway route tables.
  - GPU Fleet Team: owner for node-level TLS configuration, KV cache interfaces, and application-level batching knobs.
  - Infra Finance: owner for egress budgets and billing alerts.
- Change process:
  - Any change to cross-region routing or egress budget >5% must open a RFC in the infra change board and include cost projection and rollback plan.

CI/CD and deployment guidance
- Pipeline steps for terraform changes that affect networking:
  1. Static analysis (tfsec, checkov).
  2. Plan with `-out` artifact; automatic plan upload to PR.
  3. Auto-approve only for tag-only changes; manual approval required for route or account list changes.
  4. Post-deploy smoke: synthetic inference traffic from a canary region to validate MTU/TLS and measure tail latency.

Testing checklist (pre-rollout)
- Validate path MTU end-to-end with 3 packet sizes and verify that fragmentation does not occur.
- Smoke test TTL and reconnect behavior under transient 5–10s BGP flap simulation.
- Verify billing projection tool returns expected delta when toggling route to blackhole in staging.

Appendix: sample monitoring queries
- Top egress accounts by bytes (PromQL example):
  sum by (account, region) (increase(network_egress_bytes_total[1h]))
- Active streaming connections (Grafana):
  sum(connection_active_streams) by (node, region)
